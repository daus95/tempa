        Settings

        Configure the AI models and run limits used by Tempa's clarification and implementation stages. These settings are stored in config.json.

        AI Models

        Model used for the Clarification stage — analyzes the specification for ambiguities and conflicts. It runs only a handful of times per project, but its output determines the validity of every plan and implementation that follows, so it defaults to the most capable model.

        Model used to automatically draft the epic/feature/task plan before implementation starts (via Start Implementation, or a replan). Runs frequently and unattended, so speed and cost usually matter more here than for Clarification.

        Model used for the Implementation stage — writing code, running QA, and verifying each feature. Runs repeatedly at high volume, per epic/feature/session.

        Run Limits

        Maximum number of features implemented in a single session run. Leave empty for no limit — the session processes all pending features for the epic until done.

        Maximum number of implementation/QA sessions allowed per epic — an anti-loop safeguard that stops Tempa from retrying the same epic indefinitely.

        Maximum number of automated rounds run when finalizing clarification (Finalized Clarification).

        Architecture Principles

        The standing rules of this project — technology choices, conventions, and quality bars that apply everywhere. Tempa prepends them to every prompt it sends: clarification, applying answers, planning, implementation, QA, and verification. That's what keeps the same rules in force across sessions that don't otherwise share memory. Optional — leave it empty and nothing is injected. Learn more →
