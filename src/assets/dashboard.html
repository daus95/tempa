          Settings

          Configure the AI models and run limits used by Tempa's clarification and implementation stages. These settings are stored in config.json.

          AI Backend & Model

          Which agentic coding CLI drives each stage — Claude Code, GitHub Copilot CLI, or OpenAI Codex CLI — which model it uses, and how much reasoning effort to ask for. The model field is free text; picking the backend just changes which suggestions are offered, so you can always type a different model id than what's suggested. Reasoning Effort's options depend on the model typed — an unsupported combination is rejected when you save.

            Used for the Clarification stage — analyzes the specification for ambiguities and conflicts. It runs only a handful of times per project, but its output determines the validity of every plan and implementation that follows, so it defaults to the most capable model.

            Used to apply already-decided answers/recommendations to the PRD/spec (clarify --apply, the apply half of --finalize) and to auto-answer unanswered findings — mechanical work compared to evaluating the PRD, so it defaults to a cheaper model. Backend/model/effort are independent of the Clarifications stage above — mechanical apply work doesn't need the same reasoning strength (or even the same CLI) as evaluate.

            Used to automatically draft the epic/feature/task plan before implementation starts (via Start Implementation, or a replan). Runs frequently and unattended, so speed and cost usually matter more here than for Clarification.

            Used for the Implementation stage — writing code, running QA, and verifying each feature. Runs repeatedly at high volume, per epic/feature/session.

            Run Limits

            Maximum number of features implemented in a single session run. Leave empty for no limit — the session processes all pending features for the epic until done.

            Maximum number of implementation/QA sessions allowed per epic — an anti-loop safeguard that stops Tempa from retrying the same epic indefinitely.

            Maximum number of automated rounds run when finalizing clarification (Finalized Clarification).

            How many rounds in a row may fail to reduce the critical + major finding count before Finalized Clarification gives up early — the remaining findings likely need a human decision rather than more automated apply passes. Raise it to let the automation keep trying for longer.

            Clarification

            Off by default. Finalized Clarification normally refuses to start while any critical finding is still open, so you have to answer and apply those yourself first — the automated evaluate/apply loop it runs is meant for mopping up remaining major findings and confirming nothing has regressed, not for unsupervised critical fixes. Turning this on lets Finalized Clarification start (and its automated loop run) even with critical findings still open, so the automation will attempt to resolve them on its own — review its answers carefully afterward. This setting only affects Finalized Clarification — Start Implementation has its own separate requirement, configured independently below under "Start Implementation".

            Enabled — Finalized Clarification can start with critical findings still open, and its automation will try to resolve them unsupervised. Double-check the results before relying on them.
